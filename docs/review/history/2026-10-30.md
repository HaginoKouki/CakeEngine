## 設計上の所感

### アーキテクチャ
今週の 3 つの変更は、いずれも「置き場所を整える」方向の変更で、層の並びや責務は変わっていない。ImGui は `externals/imgui/imgui.vcxproj` の静的ライブラリになり、CakeEngine 本体のプロジェクトは外部ライブラリのソースを直接持たなくなった。SRV の払い出しは `Reserved` の固定番号と `TextureManager` の手製カウンタから `SrvManager` に一本化され、`ImGuiManager` と `SceneRenderTarget` も「番号を受け取って控える」同じ作法になった。数学ライブラリは「型」と「型に対する計算」をファイルと名前空間で分け、型のヘッダどうしは前方宣言だけで済む形になった。

### 良い点
`SrvManager` は SRV の予約枠という構成依存の定数を消し、Debug と Release で番号が変わることを前提にした設計になっている。ImGui 1.92 以降がテクスチャごとに SRV を要求する変更にも、4 枠の貸し出しで対応できた。数学ライブラリの分割は、型の静的関数に計算が集まって肥大化する前に手を打ったもので、`constexpr` 化と値渡しの統一も含めて一貫している。`Transform` の名前衝突を `TransformCoord` で避けた判断もコミットメッセージに理由が残っている。issue.md の高 1 件（Multiply のフォールスルー）と低 1 件（HackGen のライセンス）が解消された。

### 懸念
(1) `SrvManager::Allocate` の上限検査が `assert` のみで、Release では落ちずに範囲外へ書く（Medium 1）。(2) Release 構成が `imgui.lib` をリンクするようになり、`USE_IMGUI` の意味（include とリンクの可否）が実態と合わなくなった（Info 7）。原因は以前からの `GizmoSystem.h` の ImGuizmo 依存で、静的ライブラリ化で表に出た形。(3) 改名の置換が UI の文字列にも当たった（Low 2）。今後の改名では、`Editor/` の表示文字列も合わせて見直す必要がある。

### 今後問題になりそうな部分
`SrvManager` に解放が無いため、将来テクスチャのアンロードやシーン切り替えで作り直す SRV が増えると、512 枠を使い切る。`generation` と同じく「アンロードは未実装」の前提に立っているので、アンロードを入れるときに `SrvManager` のフリーリストも同時に要る。数学ライブラリは、型を足すたびに `Math::` の同名関数が増える構造なので、`Math.h` を include する `.cpp` が増えるとコンパイル時間が伸びる。現状 `Math.h` を include するのは 13 ファイルで、問題になる規模ではない。

### 今後の拡張に向けて検討すべきこと
(a) `SrvManager::Allocate` を「失敗を返せる」形にし、Release でも検出できるようにする。(b) `GizmoSettings` の ImGuizmo 列挙をエンジン側の列挙にして、Scene 層と Release 構成から ImGui を外す。(c) `Quaternion` 系の関数を `TransformComponent` の回転に使うなら、`Transform::rotate`（オイラー角）との併存方針を決めてから `SceneSerializer` と `PropertyDrawer` に手を入れる。(d) 改名を伴う変更の後は、`Editor/` の表示文字列と `docs/` の関数名を一緒に検索する。
