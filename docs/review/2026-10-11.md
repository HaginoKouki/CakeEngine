## 要確認事項
1. **Development 構成から `ENABLE_EDITOR` を外したのは意図か**（`ab0631f`）。コミット名は「リリースビルドで ImGui がビルドされる問題」で Release に関する変更だが、Development の定義も変わっている。EditorLayer.md と BuildConfig.h は「Development = ENABLE_EDITOR + USE_IMGUI」。意図なら Editor 側の guard 修正が必要、誤りなら 1 行戻せば CI が復旧する見込み（High 2）。
2. Emission 無効中にタイマーを溜め、再有効化時にまとめて出す挙動は仕様か（High 3）。Unity の `emission.enabled` は溜めない。
3. `burstCount` が `float` なのは意図か（Medium 8）。`burstCount < 1`、`rateOverTime = 0` のときの期待動作（何も出さない／エラー扱い）。
4. `BlendMode::Multiply` の `break` 欠落は意図的なフォールスルーか（High 4）。意図的なら Multiply を enum から外すかコメントが必要。
5. `startSpeed` は「速さ」か「各軸のスケール」か（Low 9）。
6. `EngineResources/textures/Sky.png`・`Sky.png.meta`・`uvChecker.png.meta` の要否。`EngineResources` に `.meta` を置く方針があるか（`skybox.png` には無い）。

## 設計上の所感
- **アーキテクチャ**: 層構造（Application > Editor / Render / Scene / Asset > Graphics / Platform > Foundation）と「データのみのコンポーネント + System + Scene 側の実行時状態」の方針は維持されている。今週のパーティクル拡張（Gradient、Color over Lifetime、ビルボード、Emission 制御）は、設定を Component、状態を ParticleStorage、描画を Pass に置く既存の分け方に正しく乗っている。Gradient を PropertyType として一般化し、インスペクタ・シリアライザ・コンポーネントの 3 箇所を規則どおり更新している点も良い。
- **良い点**: Gradient のキー順を「保存順」と割り切り、`Sorted()` を使う側に任せる判断とその理由がヘッダに書かれている。ParticlePass が状態を変更しない規則（2 ビュー対策）、`drawColor` を毎フレーム再計算して ON/OFF の切り替えに耐える設計も妥当。CI が入り、Debug / Release は毎 push でビルド確認されるようになった。
- **懸念**: (1) パーティクルの発生ロジックは、下限・上限・無効中のタイマーの 3 点で安全装置が外れた状態で、インスペクタ操作だけでハング（Critical 1）やバッファ枯渇（High 6）に届く。パラメータが Unity 風に増えるほど、`CAKE_PROPERTY_MIN` だけでなく System 側での clamp が必須になる。(2) ビルド構成の軸（USE_IMGUI / ENABLE_EDITOR）が 2 本あるのに、Editor 内の guard がファイルごとに揺れており（Inspector は USE_IMGUI、EditorDrawContext は ENABLE_EDITOR）、構成を 1 つ変えただけでビルドが壊れた。どの組み合わせを公式に支える構成とするかを BuildConfig.h に固定するべき。(3) 失敗が常態化した CI（Development、CheckUnwantedFiles）は、今後の本当の失敗を見逃す原因になる。
- **今後問題になりそうな部分**: FrameConstantBuffer（1 MiB 固定）はインスタンシング用途の拡大に耐えない。ParticlePass は Opaque の後にエミッター順で描くだけでソートが無いため、複数エミッターや Normal ブレンドの重なりで前後関係が崩れる。`Particle` の `rotate` / `scale` を使い始めると `ParticleForGPU`（約 144 B）はそのまま使えるが、System 側に Size / Rotation over Lifetime の評価が増え、`UpdateParticleSystems` が肥大化する。
- **今後の拡張に向けて**: パーティクルのモジュール（Emission / Color / Size / Rotation …）を Unity と同様に増やす前に、「1 エミッターあたりの上限」「パラメータの clamp は System 側で行う」「無効中の状態の扱い」を規則として SceneLayer.md に書き、`UpdateParticleSystems` を「更新 / 消滅 / 発生 / 色評価」の関数に分割しておくと、要確認 2・3 のような判断を局所化できる。Gradient の `Sorted()` を毎フレーム呼ぶ設計は 8 キーなら問題ないが、キー数を増やす場合は保存時に並べ替える方針への切り替えを検討する。
