## 設計上の所感

### アーキテクチャ
今週はアセットシステムの作り直し（`docs/plans/AssetSystem.md`）のフェーズ 1「土台」が動き始めた週で、JobSystem、DeferredReleaseQueue、CommandManager のフェンス値の取得口、Tests と 2 本の CI、Common.props が入った。計画書の手順 4、5、8 に当たる。手順 6（SrvManager の空きリスト化）、7（UploadQueue）、GraphicsDebugWindow、9（計測）は未着手で、DeferredReleaseQueue は `RunFrame` にまだつながっていない。これとは別に、課題提出用のパーティクルデモ（シーンとゲーム側コンポーネント 2 つ、加算合成のシェーダー定義）が追加された。

### 良い点
JobSystem は「ワーカーは作業だけ、完了処理はメインスレッドだけ」という線を API の形で守っており、計画書 7 章の「格納基盤に触れるのはメインスレッドだけにしてロックを不要にする」の前提になる。`WaitFor` がメインスレッドで作業を手伝い、ほかの完了処理は実行しない、という細かい約束までテストで固定されている。Foundation 層に置いた初版を、COM の初期化とスレッド名が Windows API に依存することを理由に Platform 層へ移した判断は、「Foundation は OS を知らない」の規則と一致する。CheckLayerIncludes は、例外一覧がそのまま残りの層違反の一覧になる形で、解消済みの行が残っても失敗するため、一覧が古くならない。Tests が `Engine/` の `.cpp` を直接リンクする構成は、上の層の関数を呼ぶとリンクで失敗するので、層の境界の検査にもなっている。設計書（PlatformLayer.md）はコードと同じコミットで更新されており、実装と一致していた。

### 懸念
(1) `CakeEngine.Common.props` の目的と実態が食い違っている（Medium 1）。本体の vcxproj が同じ設定を持ち続けているため、props を直しても本体には効かず、Tests だけが変わる。計画書が AssetPipeline.vcxproj を足す前に片付けたい。(2) JobSystem の停止が各層の破棄より後になる（Low 5）。今は呼び出し元が無いので無害だが、フェーズ 2 で AssetManager が作業を投げ始めると問題になりうる。終了順は計画書 12 章に書かれているが、`work` が何を捕まえてよいかは書かれていない。(3) 層の規則の正が InternalDesign.md と計画書 2 章の 2 か所にある（Info 7）。CI は計画書を参照しており、InternalDesign.md は「どちらを上とみなすか決められない」のまま残っていた。今回 InternalDesign.md に検査の説明を足したが、規則の文言そのものは計画書側にある。

### 今後問題になりそうな部分
`PumpMainThread` の予算 2 ms は仮の値で、フェーズ 1 手順 9 の計測待ちである。60 FPS 固定（16.7 ms）の中で、完了処理が GPU リソースの生成を含むようになると、1 件あたりの時間が予算を超えても「最低 1 件は実行する」規則で実行されるため、フレームが伸びる。予算の値と、1 件が重い完了処理を分割するかを、計測と一緒に決めることになる。`WaitFor` はメインスレッドで作業を実行するため、COM を前提にした作業（Media Foundation など）は、`Application` の `ComScope`（MTA）の下では問題ないが、Tests の main のように COM を初期化していないスレッドで走ると挙動が変わる。テストで COM を使う作業を書くときに注意が要る。

### 今後の拡張に向けて検討すべきこと
(a) `CakeEngine.vcxproj` の重複設定を消し、props を唯一の置き場所にする。(b) `Application::Run` の末尾で JobSystem を明示的に止めるか、`work` の捕捉に関する規則を書く。(c) 層の規則を InternalDesign.md に一本化し、CheckLayerIncludes のコメントと計画書はそこを参照する。(d) `ProjectSettings.json` の課題用の値を戻す時期を決める。(e) `DeferredReleaseQueue` を `RunFrame` へつなぐときに、`Renderer::EndFrame` の後の `CloseFrame` と、次フレーム先頭の `ReleaseCompleted` の位置を InternalDesign.md の 1 フレームの流れに書き足す。
