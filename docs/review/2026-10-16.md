## 要確認事項
1. **`9ae3068`（BlinnPhong）は実行して確認したか**（Critical 1）。コミットされた HLSL は VS / PS とも DXC でコンパイルできない内容で、ローカルの作業ツリーと差がある可能性がある。法線行列を「C++ で逆転置を渡す」か「一様スケール前提で `World` のまま」のどちらにするかも決めが必要。
2. `shininess` の UI 範囲 0〜1 は意図か（Medium 4）。指数として使うなら既定値と範囲を変える必要がある。
3. `.github/workflows/Development.yml` を削除してよいか（Low 7）。
4. `externals/imgradient` と `externals/imgui/ImGradient`（ImGuizmo 同梱）のどちらを Gradient 編集に使う予定か。未使用のまま残すか（Low 10）。
5. 前回からの継続: `BlendMode::Multiply` のフォールスルー（High 2）、粒の上限（High 3）、`startSpeed` の意味（速さか各軸スケールか）、`Sky.png` の要否、`System/` フォルダの最終形。いずれもコード上の変化なし。
6. Field は全エミッターの粒に効き、絞り込みが無い（ヘッダコメントに明記あり）。コライダーの layer / mask のような仕組みを将来入れる想定か。SceneLayer.md には現状どおり「全エミッターに効く」と書いた。
7. HackGen のライセンスファイルを同梱するか（Low 9）。
8. `ReadProperty` の `Int` が小数を黙って捨てる挙動を残すか（Low 8）。

## 設計上の所感
- **アーキテクチャ**: 層構造と「データのみのコンポーネント + System + Scene 側の実行時状態」は今週も守られている。Field は「設定は `ParticleForceFieldComponent`、適用は `UpdateParticleSystems`、絵は `GizmoSystem` → `GizmoDrawList`」と既存の分け方どおりに置かれ、範囲の解釈を BoxCollider と揃えている点も一貫している。前回指摘した発生ロジックの3つの安全装置（下限・無効中のタイマー・int 化）が全部入り、Development 構成の削除で CI の常時失敗も解消した。
- **良い点**: Field をフレーム先頭で1回集めて `FieldEntry` に逆行列を持たせる構成は、粒数 × Field 数の計算で無駄が無い。`SetCamera` をフレーム定数バッファの別アドレスに書く判断は、同一フレームで2ビューを描く既存の制約（`ParticlePass` の規則と同じ）を正しく踏まえている。CheckUnwantedFiles が実際に混入を止めた。
- **懸念**: (1) HLSL は実行時コンパイルなので、CI が緑でも起動できないコミットが main に入る（Critical 1）。シェーダーが増えるほどこの穴は広がる。(2) `Renderer::SetCamera` / `CameraForGPU` は、エンジン側の構造体がゲーム側シェーダーの cbuffer と対で決まっている。b0 / b1 と同様に「b2 のレイアウトはエンジンの契約」として固定し、Standard シェーダーにも同じ定義を置くか、少なくともドキュメントに書いておかないと、次にゲーム側で b2 を別用途に使ったときに気づけない（今回 GraphicsLayer.md / RenderLayer.md に記載した）。(3) パーティクルのパラメータは「下限は入ったが上限が無い」状態が続いており、Field による加速で粒が範囲外へ飛ぶ・溜まるケースも含め、粒数と速度の上限を System 側で持つ段階に来ている。
- **今後問題になりそうな部分**: CI でシェーダーをコンパイルしていない（`dxc` を GitHub Actions の Windows ランナーで走らせれば `Assets/Shaders` と `EngineResources/shaders` の全ファイルを検証できる）。Field が全エミッターに効く設計は、エミッターが増えると「この Field はこのエフェクト専用」が書けなくなる。`externals/` に用途の重なるライブラリ（2 つの ImGradient）が増え始めている。
- **今後の拡張に向けて**: (a) `ShaderCompiler` のエラーを `assert` ではなく「エラーシェーダーへ差し替えて続行」にすると、MaterialManager の errorMaterial と同じ「欠損が見える状態で動く」方針に揃う。(b) 法線行列を C++ 側で計算して `TransformationMatrix` に足すなら、Standard / Object3D / Particle の VS で cbuffer 定義を共有ヘッダ（`.hlsli`）にまとめる時期。(c) Field に layer / mask か「対象エミッターの `EntityRef`」を持たせる前に、Field の適用順と合算の規則（現状は単純加算）を SceneLayer.md に固定しておく。
